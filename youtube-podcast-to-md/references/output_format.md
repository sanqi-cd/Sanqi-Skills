# Markdown 输出格式规范

---

## 通用头部（两种模式共用）

```markdown
# {视频标题（中文翻译）}

> 📺 原标题：{English Title}
> 👤 频道：{Channel Name}
> ⏱ 时长：{X} 分钟
> 📅 发布：{YYYY-MM-DD}
> 🔗 链接：{YouTube URL}
> 📝 整理模式：精简版 / 完整版

---

## 📌 核心摘要

{3-5 句话，概括本期播客的核心主题、最重要结论、值得关注的理由}

> ⚠️ **准确性说明**：本文档有 N 处标注了不确定性标记（如“原文不清”“原文: xxx”等），建议在使用关键结论前回溯原视频核对。

---

## 🗂 内容目录

- [章节一标题](#anchor1)
- [章节二标题](#anchor2)
- ...

---

## ⚡ 关键要点

- **要点一**：一句话说明
- **要点二**：一句话说明
（共 5-8 条）

---
```

---

## 模式 A：完整版正文格式

### 核心原则

**高保真还原对话**——保留对话的时间线结构、说话人切换、论述递进关系。是"精校翻译的对话录"而非"概括转述"。

### 正文格式

```markdown
## {章节标题 — 概括本章节的核心话题}

### {小节标题}

> 🕐 00:00 - 05:30

**主持人：** 你对这个话题的看法是什么？

**嘉宾：** 我认为核心问题在于三个方面。第一，……第二，……第三，……

> 💡 特别精彩的论断用引用块呈现

**主持人：** 这个观点很有意思，能不能展开说说第一点？

**嘉宾：** 当然。……（详细论述） [?原文不清] 转录疑似有误，请回溯核对

### {小节标题}

> 🕐 05:30 - 12:15

正文内容……

**重要数据或结论加粗。**
```

### 格式规则

| 规则 | 说明 |
|------|------|
| 时间戳标注 | 每个 `###` 小节下方标注 `> 🕐 MM:SS - MM:SS`，取自原文 `[TS:MM:SS]` 标记 |
| 说话人标注 | 每次发言以「**说话人：**」开头，同一人连续发言合并 |
| 对话保留 | 保留问答、反驳、补充等对话互动，不合并为第三人称叙述 |
| 轻度整理 | 去除口头禅和重复表达，但不改变对话顺序和论述结构 |
| 段落长度 | 单段 2-5 句话，避免文字墙 |
| 引用块 | 仅用于特别精彩或反常识的观点，每章 1-3 处 |
| 不确定性标记 | 疑点处标注 `[?原文不清]`、`[?原文: xxx]`、`[?指代不明: xxx]`、`[?说话人待确认]` |

---

## 模式 B：精简版正文格式

### 核心原则

**提取核心价值**——按主题归类，用结构化方式呈现观点、数据和结论。是"精华速览"而非"时间线记录"。

### 正文格式

```markdown
## {章节标题 — 概括本章节的核心话题}

### {小节标题}

> 🕐 00:00 - 05:30

- 核心观点一：简明阐述（1-2 句） [→04:32]
- 核心观点二：简明阐述（1-2 句）
- **关键数据**：具体数字及含义 [→06:15]

> 📊 重要数据或统计

### {小节标题}

> 🕐 05:30 - 12:15

- 核心观点……
- 核心观点…… [?原文不清] 转录疑似有误

> ⚠️ 如有重要前提或反常识结论，用此格式标注

💡 **可借鉴的做法：**
1. 具体建议一 [→10:45]
2. 具体建议二
```

### 格式规则

| 规则 | 说明 |
|------|------|
| 时间戳标注 | 每个 `###` 小节下方标注 `> 🕐 MM:SS - MM:SS`；重要观点末尾标注 `[→MM:SS]` 方便回溯 |
| 主题归类 | 围绕同一主题的观点集中呈现，不严格按时间线 |
| 列表为主 | 用无序列表（`-`）呈现观点，每条独立成意 |
| 信息密度 | 精炼至原文 30-40%，每个字都有信息量 |
| 说话人 | 不逐句标注说话人，仅在观点归属重要时注明「XX 认为……」 |
| 行动导向 | 如有可操作的建议，单独列出 |
| 不确定性标记 | 疑点处标注 `[?原文不清]`、`[?原文: xxx]`、`[?可能指xxx]` |

## 通用尾部（两种模式共用）

```markdown
---

## 💬 精彩金句

> "{金句一（中文翻译）}"
> — {说话人}，约 {时间点}
> *"{英文原文}"*

> "{金句二（中文翻译）}"
> — {说话人}，约 {时间点}
> *"{英文原文}"*

（至少 3 条，完整版可放 5-8 条，保留中文与原文对照）

---

*本文档由 YouTube 字幕自动整理生成 · 使用 youtube-podcast-to-md skill*
```

## 标题层级规范

| 级别 | 精简版用途 | 完整版用途 |
|------|-----------|-----------|
| `#` | 文档标题（仅一个） | 文档标题（仅一个） |
| `##` | 主题章节（3-6 个） | 主题章节（3-6 个） |
| `###` | 章节内细分话题 | 章节内细分话题 / 自然分段 |
| `####` | 避免使用 | 仅在极复杂内容中使用 |

---

## 强调与标注规则

| 格式 | 用途 | 示例 |
|------|------|------|
| `**加粗**` | 数据、核心结论、专有名词首次出现 | **300 万用户**、**联邦学习** |
| `*斜体*` | 书名、专辑名、文章标题 | *The Lean Startup* |
| `` `代码` `` | 技术术语、命令、工具名 | `Kubernetes`、`GPT-4` |
| `> 💡` | 精彩观点 | 金句、独特见解 |
| `> ⚠️` | 重要警告或反常识结论 | 需特别注意的前提或风险 |
| `> 📊` | 重要数据或统计 | 关键数字、对比数据 |
| `> 🕐` | 小节时间范围（标注于 ### 标题下方） | `> 🕐 05:30 - 12:15` |
| `[→MM:SS]` | 观点/数据的精确回溯点（精简版） | `核心结论…… [→08:45]` |
| `[?原文不清]` | 疑似转录错误的句子 | 语义不通处 |
| `` `[?原文: xxx]` `` | 无法确定翻译的英文术语 | 保留原文供核对 |
| `[?指代不明: xxx]` | 无法确定所指的代词 | this/that/it 等 |
| `[?说话人待确认]` | 无法确定说话人身份 | 多人对话场景 |

## 文件命名规范

```
{频道名}_{视频标题前20字}_{YYYYMMDD}_{mode}.md
```

示例：
```
HubermanLab_睡眠优化的科学指南_20250514_full.md
Y-Combinator_创业公司最常见的错误_20250514_summary.md
```

特殊字符（`/` `\` `:` `*` `?` `"` `<` `>` `|`）替换为 `_`。

## 质量检查清单

在输出最终文档前，确认以下项目：

**通用检查项：**
- [ ] 文档头部元数据完整（标题、频道、时长、链接、模式）
- [ ] 核心摘要存在且准确（3-5 句）
- [ ] 准确性说明存在（统计了不确定性标记数量）
- [ ] 目录与正文标题一致，锚点可跳转
- [ ] 标题层级正确（`##` → `###`，不跳级）
- [ ] 每个 `###` 小节下方有时间戳标注 `> 🕐`
- [ ] 无大段未分段文字块（单段不超过 150 字）
- [ ] 数据、专有名词有加粗标注
- [ ] 不确定性标记使用正确格式（`[?原文不清]`、`[?原文: xxx]`、`[?指代不明]`、`[?说话人待确认]`）
- [ ] 金句部分存在且不少于 3 条
- [ ] 文档结尾有来源说明
- [ ] 文件名符合命名规范

**完整版额外检查项：**
- [ ] 对话结构完整（说话人标注清晰，对话逻辑连贯）
- [ ] 无信息遗漏（每个实质性观点都被保留）
- [ ] 论述链条完整（逻辑转折、因果关系清晰）

**精简版额外检查项：**
- [ ] 关键要点 5-8 条，每条独立成意
- [ ] 重要观点/数据末尾有 `[→MM:SS]` 回溯标记
- [ ] 信息精炼到位（无冗余、无废话）
- [ ] 核心观点突出（读者扫一眼就能抓住重点）
