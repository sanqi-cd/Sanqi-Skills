# Prompt 模板文件

本文件包含 Step 5 中模型处理各字幕块时使用的 prompt。
根据用户选择的模式选用对应模板。

---

## 模式 A：完整版（full）

适用于：高保真还原完整对话，保留所有论述过程和对话结构。

### 单块处理 Prompt

```
你是一位专业的播客翻译整理专家。你的任务是将以下播客字幕片段**高保真还原**为自然流畅的中文对话。

## 当前片段信息
- 时间段：{start_time} ~ {end_time}
- 这是第 {chunk_index}/{total_chunks} 块
- 前文已讨论的主要话题（按出现顺序）：
{previous_topics}

## 还原要求

**信息保真（最重要）：**
1. 保留对话中的每一个实质性观点、论据、数据、例子、引用——不要遗漏任何有价值的信息
2. 将原文口语翻译为自然的中文书面对话，保持原意的精确性
3. 识别并标注说话人切换：多人对话用「**主持人：**」「**嘉宾A：**」等格式；单人讲述则无需标注
4. 保留对话中的逻辑转折（但是、然而、另一方面等），确保论述链条完整

**去除噪音：**
1. 删除纯口头禅和填充词：若原文为英文，可删除 "you know"、"like"、"I mean"、"basically"、"right?" 等；其他语言按同类口语噪音处理
2. 删除重复表达：同一句话换个说法又说一遍的，保留更清晰的那遍
3. 删除无实质内容的寒暄（除非反映了对话的氛围转折）

**原文校验（重要）：**
1. 原文可能存在自动字幕的断句和识别错误。如果相邻两句话义不连贯，请按语境推断纠正——明显缺失主语的句子补全主语，明显被错误切断的句子合并
2. 如原文中有专有名词、数字、技术术语，请重点核对是否合理（如"four point five"可能是"GPT-4.5"而非"四点五"）

**准确性标注（重要）：**
1. 语义不通、明显是转录错误的句子 → 在该句后标注 [?原文不清]
2. 无法确定中文翻译的专业术语 → 保留英文原文并标注 `[?原文: xxx]`
3. this/that/it 等指代词无法根据上下文确定所指 → 标注 [?指代不明: 可能指xxx]
4. 说话人身份无法确定 → 标注 [?说话人待确认]

**结构与可读性：**
1. 根据话题变化自然分段，每段加一个概括性的 ### 三级标题
2. 每个 ### 小节下方用原文中的 `[TS:MM:SS]` 时间戳标注起止时间：`> 🕐 MM:SS - MM:SS`
3. 段落控制在 2-5 句话，避免大段文字墙
4. 关键数据、专有名词、核心结论用 **加粗** 标注
5. 特别精彩或反常识的观点用 > 引用块突出呈现

**格式要求：**
- 输出标准 Markdown
- 不要添加"接下来讲到……""然后他们聊到……"等过渡语
- 标题要具体概括内容，不要用"第一部分""第二个话题"这类空洞标题

## 字幕原文

{transcript_chunk}

## 输出
直接输出整理好的中文 Markdown 内容，从 ### 标题开始，不要加任何前言或解释。
```

## 模式 B：精简版（summary）

适用于：快速获取核心信息，提取最有价值的观点和结论。

### 单块处理 Prompt

```
你是一位专业的播客内容提炼专家。你的任务是从以下播客字幕中**提取核心信息**，整理为简洁有力的中文摘要。

## 当前片段信息
- 时间段：{start_time} ~ {end_time}
- 这是第 {chunk_index}/{total_chunks} 块
- 前文已讨论的主要话题（按出现顺序）：
{previous_topics}

## 提炼要求

**内容筛选：**
1. 只保留有实质价值的观点、数据、结论、建议、独特见解
2. 过滤：闲聊、铺垫、重复论述、过度展开的举例（除非例子本身极具启发性）
3. 每个独立观点用 1-3 句话表达，简洁有力，说清"是什么"和"为什么重要"
4. 提炼比例约为原文的 30-40%

**原文校验（重要）：**
1. 原文可能存在自动字幕的断句和识别错误。如果相邻两句话义不连贯，请按语境推断纠正
2. 如原文中有专有名词、数字、技术术语，请重点核对是否合理

**准确性标注（重要）：**
1. 语义不通、明显是转录错误的句子 → 标注 [?原文不清]
2. 无法确定中文翻译的专业术语 → 保留英文原文并标注 `[?原文: xxx]`
3. 不确定具体所指的代词或概念 → 标注 [?可能指xxx]

**结构组织：**
1. 每个独立话题用 ### 标题标注，标题后附带原文时间范围：`> 🕐 MM:SS - MM:SS`
2. 核心观点用无序列表（`-`）呈现，每条独立成意。重要观点或数据末尾标注原文时间点 `[→MM:SS]`，方便回溯核实
3. 数据、专有名词、核心结论用 **加粗** 标注
4. 如有可操作的建议或行动项，在末尾用「💡 可借鉴的做法」单独列出
5. 如观点的前提假设很重要，用「⚠️ 前提」标注

**格式要求：**
- 输出标准 Markdown
- 不要加过渡语
- 标题要精准概括话题内容

## 字幕原文

{transcript_chunk}

## 输出
直接输出精简版中文 Markdown 内容，从 ### 标题开始，不要加任何前言或解释。
```

## 最终整合 Prompt（两种模式通用）

在所有分块处理完毕后，用此 prompt 做全局整合：

```
你是一位资深文档编辑。以下是一期播客分块整理后的各段中文内容，请将它们整合为一篇完整、连贯的文档。

## 视频信息
- 标题：{title}
- 频道：{channel}
- 时长：约 {duration} 分钟
- 链接：{url}
- 整理模式：{mode_label}（{summary_or_full}）

## 整合要求

1. **调整结构**：
   - 将全文按主题归并为若干章节（3-6 个 ## 二级标题）
   - 各章节内的小节使用 ### 三级标题
   - 合并相邻的相同话题、消除分块造成的重复表述
   - 标题之间不重复、不重叠

2. **优化衔接**：
   - 补充必要的过渡句，消除分块边界造成的断裂感
   - 确保同一论述链条的完整性（别让一个论点被标题分隔开）

3. **生成文档头部**（放在正文之前）：
   ```
   ## 📌 核心摘要
   （3-5 句话，概括整期播客的核心主题、最重要结论和值得关注的理由）

   ## 🗂 内容目录
   （自动生成，用锚点链接到各 ## 章节标题）

   ## ⚡ 关键要点
   （全文最重要的 5-8 个观点/结论，每条一两句话，用无序列表）
   ```

4. **生成文档尾部**：
   ```
   ## 💬 精彩金句
   （从全文中选出 3-5 句最具启发性或最精辟的话，用 > 引用块呈现，保留中文与原文对照）
   ```

5. **全文润色**：
   - 统一术语翻译（同一个英文词在全文中用同一个中文译法）
   - 补充必要的中文语境说明（如欧美文化梗、行业缩写），用括号注在后面

6. **准确性回溯说明**（重要）：
   - 统计全文中 `[?原文不清]`、`[?原文: xxx]`、`[?指代不明]`、`[?说话人待确认]` 的出现次数
   - 在文档头部的「核心摘要」下方添加一行提示：**>>> 准确性说明：本文档有 N 处标注了不确定性标记，建议在使用关键结论前回溯原视频核对 <<<**
   - 保留各分块中的时间戳标注（`> 🕐` 和 `[→MM:SS]`），确保回溯时能定位到原文

## 各块内容

{all_chunks_content}

## 输出
输出完整的、可直接使用的 Markdown 文档。从文档标题（# 标题）开始，不要有任何前言或解释。
```

## 变量说明

| 变量 | 说明 | 示例 |
|------|------|------|
| `{start_time}` | 当前块的开始时间 | `00:00` |
| `{end_time}` | 当前块的结束时间 | `05:00` |
| `{chunk_index}` | 当前块编号（从 1 开始） | `3` |
| `{total_chunks}` | 总块数 | `12` |
| `{previous_topics}` | 前 3 个已处理块的主题/标题列表，用逗号或分号分隔 | `AI 监管现状；开源模型的崛起；数据隐私挑战` |
| `{transcript_chunk}` | 当前块的清洗后字幕文本 | — |
| `{title}` | 视频标题（中英双语） | — |
| `{channel}` | 频道名称 | — |
| `{duration}` | 视频时长（分钟） | `45` |
| `{url}` | 视频链接 | — |
| `{mode_label}` | 模式中文标签 | `完整版` 或 `精简版` |
| `{summary_or_full}` | 模式英文标识 | `full` 或 `summary` |
| `{all_chunks_content}` | 所有分块整理结果的拼接文本 | — |

### `{previous_topics}` 构建规则

- 为当前块准备上下文时，提取前 3 个已处理块的 **### 标题列表**
- 若前面不足 3 块，有多少给多少
- 格式示例：
  ```
  - AI 监管的全球现状与分歧
  - 开源模型对中小企业的价值
  - 数据隐私与模型训练的平衡
  ```
